# 历史对话决策回收

来源：`trellis mem` 对 Codex 会话 `019feb48-463b-70f1-8ded-85b87d33d5dd` 与 `019fdb58-3805-7f90-8ffd-1eb483963e17` 的只读检索，2026-08-11。

## 已明确的用户目标

1. 用户主要在 Clash Verge 中手动测速、手动选择，不以自动组作为主要使用方式。
2. GitHub 负责尽可能收集更多亚洲候选，重点为香港、日本、韩国、新加坡和台湾；不能因单轮 Timeout 删除亚洲候选。
3. CNB 负责回答“哪些节点值得优先手动测速”，对全部候选执行 GMGN 20 轮测试。
4. `https://gmgn.ai/` 是体验目标；单轮只有 `<=1000 ms` 才算合格。实现可以等待到 3000 ms 来区分慢响应和无结果，但超过 1000 ms 不能计为通过。
5. 亚洲应比非亚洲宽松；非亚洲保留最稳定的 10–20 个。
6. 80 是期望容量，不是硬下限；质量足够时可以扩展到 100–150，质量不足时允许更少。
7. CNB 应尽量利用并发、分片和可用性能；只有出现实际平台瓶颈时才考虑拆仓库。
8. 节点对 CNB 出口差、不代表对用户本地出口差。`ASIA-KEEP KR 012` 是具体反例，因此需要候补和历史保护，而不是简单降低主力门槛。
9. gstatic 在 V2 rollout 完成前保留为回滚对照；连续 3 次有效 GMGN 影子通过并经用户确认迁移后停止自动更新，但不删除旧分支或 URL，只冻结最后一版并保留受控手动恢复。

## 已讨论并接受的保护措施

- 独立 GMGN 影子运行，不先覆盖旧订阅。
- 真实出口地区验证，不能长期只信节点名称。
- Timeout/慢响应必须进入评分与诊断。
- 20 轮应覆盖真实观察时间，不是几十秒的瞬时采样。
- 亚洲异常先降候补，连续 2–3 次差才移除，恢复后自动回主力。
- 限制同出口 IP、服务器、ASN 和来源的集中度。
- 不为达到 80 个降低主力质量标准。
- 输出应面向手动选择，包含港、日、韩、新、台、亚洲候补、非亚洲稳定和全部入选分组，名称不附加每次变化的测速数字。

## 已落实并经过真实运行验证的基线

- 四分片并行 GMGN 20 轮影子测试已经运行成功。
- 当前正式 GMGN 输出与旧 gstatic 输出隔离，失败不会覆盖旧订阅。
- 当前初始门槛：亚洲核心 `>=14/20` 且前后半程各 `>=5`；亚洲弹性 `10–13/20`；非亚洲基础 `>=16/20`，扩展 `>=18/20`。
- 当前排序以达标次数、响应次数、P90、中位数和抖动为序。
- 真实运行表明不能为了达到 80 个强行加入全失败节点。

## 历史上出现的误解，规划必须消除

- GitHub 全候选池不是最终优选订阅。
- 旧 `clash-cn-output` 是 gstatic 选拔结果，即使其 Clash `automatic` 组使用 GMGN 实时测速。
- 新 `clash-cn-gmgn-output` 才是 CNB GMGN 20 轮正式结果。
- 刷新旧订阅不会自动切换到新分支；分组名与订阅地址必须能让用户立即识别。
- “流水线稳定运行”只表示任务、校验、失败保护和发布链路可工作，不表示八项保护全部实现，也不表示所有用户本地测速都稳定。

## 仍需在本规划中解决

- 完整跨运行历史状态，而不是只读取上一版分组。
- 亚洲候补的准入和容量规则。
- 真实出口与多样性数据流。
- 可映射到公开节点名称的安全淘汰原因。
- 地区分组、稳定名称和订阅辨识。
- GMGN 正式任务自动调度；当前不能依赖人工触发。
