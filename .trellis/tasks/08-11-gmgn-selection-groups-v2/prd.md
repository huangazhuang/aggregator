# GMGN 真实地区选择与分组

## Goal

把一轮已经通过有效性门禁的 GMGN 20 轮结果，转换成面向 Clash Verge 手动选择的、可解释且稳定的正式候选集合：真实亚洲出口使用亚洲分层规则，新亚洲节点只要本轮至少一次响应即可进入宽松手动候补；非亚洲只保留最稳定的 10–20 个；最终总数不超过 150，80 只是期望容量而不是降标理由。

本子任务不重新采集节点、不执行 GMGN 测量，也不维护跨运行历史；它只消费上游冻结的候选、有效运行、身份/历史契约，完成真实地区解析、选择、多样性、分组和脱敏选择诊断。

## Dependencies

- 必须等待 `08-11-github-candidate-provenance-v2` 冻结 `clash.yaml + status.json + candidate-metadata.json` 三件套、来源证据、`source_id`、`server_id` 与 `endpoint_id` 契约；本任务不引入 `candidates.jsonl` 或第二份代理载荷。
- 必须等待 `08-11-gmgn-measurement-validity` 冻结 `valid_run=true` 的节点汇总、错误趋势、20 轮统计和观察窗口契约；无效运行不得进入本选择器。
- 必须等待 `08-11-gmgn-history-identity` 冻结稳定 identity、公开 HMAC diagnostic ID、`history.json`、稳定 `output_name` 和历史保护状态机接口。
- 本任务完成并冻结选择/bundle 输入接口后，`08-11-gmgn-publication-orchestration-v2` 才能接入正式事务发布。

## In Scope

- 对本轮有响应节点、严格层候选和历史保护候补执行真实出口 IP、国家/地区与 ASN 查询；原始 IP/cache 只留在非公开受控状态，公开 history 只引用 C3 生成的 HMAC `candidate_id`/`exit_id`。
- 将节点划分为亚洲核心、亚洲弹性、亚洲手动候补、历史保护候补、非亚洲稳定或未入选状态。
- 应用亚洲宽松、非亚洲严格、80/150 容量和故障域多样性政策。
- 生成固定目标分组、稳定节点引用和脱敏 `node-status` 选择原因。
- 为查询失败、过期缓存、地区证据冲突、容量裁剪和多样性裁剪提供确定性降级与诊断。

## Out of Scope

- 修改 GitHub 来源收集、候选发布门禁或 provenance 生成。
- 修改四分片、20 轮、GMGN 目标、1000 ms 阈值、观察窗口或 `valid_run` 判定。
- 自行计算另一套 fingerprint、更新 bad-run streak 或重新命名已有稳定 identity。
- 修改 `.cnb.yml`、GitHub/CNB 触发器、远端分支、事务发布或 gstatic 生命周期。
- 为达到 80 个而自动降低任何质量阈值，或把亚洲候补放入自动组。

## Requirements

### R1. 输入与失败关闭

- 选择器只接受 schema/policy 受支持、`identity_epoch` 与 `identity_key_version` 均已知且 `valid_run=true` 的输入；run ID、source profile SHA、main SHA、候选 identity 与 20 轮汇总必须一致。两个 identity 字段语义独立，缺一或迁移未知都失败关闭。
- 缺失候选 metadata、未知 schema、重复 identity、统计不守恒、历史状态损坏或稳定名称映射冲突时必须失败关闭，不生成可发布 bundle。
- 名称、上一版代理组和随机 shadow ID 都不得作为身份或历史来源；必须消费 C1/C3 的稳定契约。

### R2. 真实地区与缓存

- 查询范围为：本轮 `response_count >= 1` 的节点、所有可能进入严格层的节点，以及仍处于历史保护窗口的亚洲候补；无需查询新出现且 20 轮零响应的节点。
- 初始出口缓存 TTL 为 7 天；历史保护节点在查询服务失败时可使用不超过 30 天的旧缓存，并标记 `stale=true`。TTL、grace 和 provider schema 都属于版本化策略；包含原始出口 IP 的 cache 不得写入生成分支。
- 只有已验证真实出口为 HK/JP/KR/SG/TW 的节点，才能进入亚洲核心或亚洲弹性。
- 查询失败时，可靠的国家专用来源证据最多允许节点进入“临时亚洲手动候补”；模糊名称或短标签不得单独获得亚洲宽松主力阈值，也不得进入已验证地区组。
- 未知地区节点若满足非亚洲严格阈值，可按未知/非目标地区走非亚洲稳定政策；否则只保留在 GitHub 候选池。
- 地区/ASN provider 故障本身不应使整轮无效，但不得伪造地区；缓存、查询失败和证据冲突必须进入脱敏诊断。

### R3. 固定分层政策

- 亚洲核心：真实出口属于五个目标地区，`within_1000_count >= 14`，且前 10 轮和后 10 轮各至少 5 次达标。
- 亚洲弹性：真实出口属于五个目标地区，`within_1000_count` 为 10–13。
- 亚洲手动候补：目标亚洲真实出口，或查询失败但具有可靠国家专用来源证据；本轮 `response_count >= 1` 且未达到亚洲弹性。即使所有响应都 `>1000 ms`，也可进入该层。
- 历史保护候补：由 C3 明确标记为仍在第 1–2 次有效零响应保护窗口内的旧亚洲节点；本任务不得自行增加或重置 streak。
- 新出现且 20 轮零响应的亚洲节点不进入 CNB 正式输出，只留在 GitHub 全候选池。
- 非亚洲稳定：按质量排序后的前 10 个必须 `within_1000_count >= 16`；第 11–20 个必须 `within_1000_count >= 18`；非亚洲总数永不超过 20，且不享受亚洲候补历史保护。
- 层内排序固定为：`within_1000_count` 降序、`response_count` 降序、P90 升序、median 升序、jitter 升序、稳定 identity 升序。Timeout/no-result 已通过前两项完整计入，不得在排序中消失。

### R4. 容量和亚洲宽松政策

- 80 仅写入状态作为期望容量；严格层不足 80 时仍可发布，禁止自动降标或拿候补冒充稳定容量。
- 最终节点总数硬上限为 150；满足质量线的亚洲核心和亚洲弹性优先保留，非亚洲仅从严格池选取 10–20 个。
- 当最终总数未超过 150 时，满足准入的亚洲手动候补和历史保护候补不得因同出口 IP、ASN、来源、server 或协议重复被硬删除，只允许降权、后排和标记集中度。
- 当总数超过 150 时，裁剪顺序固定为：亚洲核心、亚洲弹性、合格非亚洲稳定、历史保护候补、当前亚洲手动候补；同层再按质量、地区缺口和故障域集中度裁剪。
- 若严格层本身超过 150，按亚洲核心、亚洲弹性、非亚洲前 10、非亚洲扩展 11–20 的顺序应用容量，并保持各层质量门槛不变。

### R5. 多样性

- 对进入 `👆手动优先测速` 的优先集合和 `GMGN自动` 使用硬限制：同一真实出口 IP 最多 3 个，同一 server 最多 3 个；同一 ASN 最多 `max(3, ceil(strict_target * 0.30))`，同一来源最多 `max(2, ceil(strict_target * 0.25))`。
- 多样性选择先尽量覆盖 HK/JP/KR/SG/TW，再按固定质量排序；不得为了满足地区或多样性覆盖引入未达到对应阈值的节点。
- 协议、运营商和线路用于同分时的覆盖优先，不设置会迫使不合格节点入选的最低配额。
- `👆手动优先测速` 只包含经上述硬限制选出的亚洲核心、亚洲弹性和非亚洲稳定；亚洲候补不进入该优先组，因此 R4 的宽松例外不会与优先组硬限制冲突。

### R6. 分组与稳定名称

- 最终配置至少包含并固定拼写：`👆手动优先测速`、`🇭🇰香港`、`🇯🇵日本`、`🇰🇷韩国`、`🇸🇬新加坡`、`🇹🇼台湾`、`🌏亚洲候补`、`🌍非亚洲稳定`、`📦全部入选`、`GMGN自动`。
- `👆手动优先测速` 包含经多样性硬限制的亚洲核心、亚洲弹性和非亚洲稳定，供用户先测更有希望的节点；亚洲候补通过 `🌏亚洲候补`、已验证地区组和 `📦全部入选` 供用户继续手动复测。
- `📦全部入选` 是唯一包含全部最终节点的总组，包含优先集合、当前亚洲手动候补和历史保护候补。
- 五个地区组只按已验证真实出口分组，可同时包含本地区主力与候补；证据不足或查询失败节点不得伪装进入地区组。
- `🌏亚洲候补` 只含当前亚洲手动候补和历史保护候补；`🌍非亚洲稳定` 只含严格非亚洲。
- `GMGN自动` 只含亚洲核心和非亚洲稳定，不含亚洲弹性、亚洲手动候补或历史保护候补。
- 节点名称必须使用 C3 的稳定 `output_name`；不得附加延迟、成功率、排名或本轮层级。空组若 Mihomo 要求非空，可使用 `DIRECT` 占位，但状态必须记录真实节点数为 0。
- 所有代理名唯一，所有组引用必须指向已发布节点、其他合法组或 Mihomo 内建目标，并通过 YAML 回读和 Mihomo 校验。

### R7. 可解释且脱敏的选择诊断

- `node-status` 必须使用同时绑定 `identity_key_version` 与 `identity_epoch` 的公开 HMAC opaque diagnostic ID，并能说明当前 profile 中每个节点的 tier、地区置信度、20 轮汇总、history transition、选择/降级/裁剪原因和集中度标记。
- 公开诊断不得包含 server、port、UUID、password、原始错误、真实出口 IP、私有订阅 URL/token 或可逆来源标识。
- 公开 `history.json` 不得包含裸 canonical fingerprint、真实出口 IP 或私密 cache；只能用 C3 的 HMAC `candidate_id`/`exit_id` 关联公开状态。
- 状态必须分别公布亚洲核心、亚洲弹性、当前候补、历史保护、非亚洲稳定、未知地区、地区计数、容量裁剪和多样性裁剪数量；候补不得计入“稳定容量”。

## Acceptance Criteria

- [ ] 合成节点精确证明 14/20 与前后半程边界、10–13/20、至少一次慢响应候补、20 次零响应新节点排除、16/20 和 18/20 非亚洲边界。
- [ ] 一个本轮仅一次 `>1000 ms` 响应的目标亚洲新节点进入 `🌏亚洲候补`、对应已验证地区组和 `📦全部入选`，但不进入 `👆手动优先测速` 或 `GMGN自动`；一个新亚洲零响应节点不进入任何 CNB 正式组。
- [ ] C3 标记的 bad streak 1–2 历史节点继续存在于候补；streak 3、confirmed missing 或 invalid config 节点不被本选择器重新引入。
- [ ] 少于 80 个严格节点仍生成合法输出且策略版本/阈值不变；任何场景总数不超过 150、非亚洲不超过 20。
- [ ] 150 以下的亚洲候补不会因同 IP/ASN/source/server 重复被硬删；超过 150 的裁剪顺序和原因可重复验证。
- [ ] 严格层的同出口、server、ASN、source 上限精确生效，且不会引入低于阈值的节点来补地区或多样性。
- [ ] 真实 HK/JP/KR/SG/TW 分组正确；查询失败、过期缓存和名称/出口冲突均走明确降级，不把模糊名称当真实亚洲主力。
- [ ] 最终配置精确包含十个目标组；`GMGN自动` 仅含亚洲核心和非亚洲稳定，所有组引用有效并通过目标 Mihomo `-t`。
- [ ] 输入重排不改变最终 identity、稳定名称、分层结果或确定性排序。
- [ ] 公开选择诊断能解释入选、降级、历史保护、容量裁剪和多样性裁剪，且敏感字段扫描为零命中。
